*clective.txt*  Language and SDK profiles for C/C++         *clective*

Clective requires Neovim 0.11+. Full documentation: README.md.
Installation: https://github.com/IstiCusi/Clective.nvim
Full Lazy example: examples/lazy.lua. Migration guide: MIGRATING.md.

COMMANDS                                               *clective-commands*

:ClectiveProfile [id]    Select project profile; omit ID for the picker.
:ClectiveProfile! [id]   Select a persistent override for the current file.
:ClectiveReset          Clear project choice and current file override.
:ClectiveReset!         Clear only the current file override.
:ClectiveInfo           Inspect effective language, paths and clangd command.
:ClectiveHeaders        Browse headers from the current context.
:ClectiveOpen [name]    Open the include under the cursor, or the given name.
:ClectiveOpen! [name]   Open in a vertical split.
:ClectiveSwitch         Ask attached clangd for the matching source/header.
:ClectiveRefresh        Reload build paths and native compiler discovery.
:ClectiveIndex          Send project source commands for clangd indexing.
:checkhealth clective   Check setup and loaded buffer contexts.

CONFIGURATION                                          *clective-setup*
>
  require("clective").setup({
    default_profile = "project",
    profiles = {
      sdk = {
        label = "My SDK", language = "c", build = "ignore",
        system_headers = false, include_dirs = { "~/sdk/include" },
      },
    },
  })
<
No leader keys are defined by the core plugin. Configure them in Lazy.
The supplied Lazy example uses Space K c (uppercase K) for project profiles.

LANGUAGE                                               *clective-language*

A .h file may be C or C++. Choose a language through its SDK profile, or use
the "project" profile to derive a context from build commands.
Explicit .c and C++ extensions retain their language.

clangd supplies symbols, definitions and references. Clective supplies analysis
commands to an existing attached client. It does not change the build compiler
or emulate unsupported Amiga/Oscar64 syntax and target ABIs.

STATUS                                                 *clective-status*
>
  require("clective").status()       -- statusline window
  require("clective").status(bufnr)  -- explicit buffer
<
State is saved below stdpath("state")/clective, not inside the plugin.
